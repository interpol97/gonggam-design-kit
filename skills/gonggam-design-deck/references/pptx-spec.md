# PPTX 규격 — 실제 .pptx 파일로 만들 때

> **HTML 뼈대(`templates/deck.html`)를 그대로 옮길 수 없다.** CSS가 통째로 사라지기 때문이다.
> 이 문서는 같은 디자인을 PowerPoint 좌표계로 옮기는 환산표와, PowerPoint가 우리 규칙을 어기는 지점을 막는 규칙이다.
>
> **판단은 그대로 간다** — 모드 3종, 한 장 한 메시지, 요소 5개, 실눈 검사, 거부 목록, 한글 문체. 바뀌는 것은 구현 층뿐이다.

---

## 0. 언제 PPTX 로 가나

| 필요 | 무엇으로 |
|---|---|
| 내가 발표하고 끝 | **HTML** (브라우저 `F` 전체화면) — 가장 빠르고 안 깨진다 |
| 배포·인쇄 | **HTML → PDF** (`P`) |
| **받는 사람이 직접 고쳐야 한다** | **PPTX** |
| 학교·기관 제출 양식이 pptx | **PPTX** |

**기본은 HTML 이다.** pptx 는 "남이 고쳐야 할 때" 만 간다. 파일이 커지고, 폰트가 깨지고, 자동 맞춤이 규칙을 어긴다.

---

## 1. 캔버스 — 첫 줄에서 정한다

```
13.333 in × 7.5 in   (= 960 × 540 pt, 16:9)
```

**슬라이드를 추가하기 전에 레이아웃부터 지정한다.** 기본 캔버스는 10인치라, 13.33인치 기준으로 잡은 좌표는 **화면 밖으로 나가고 경고도 안 뜬다.** 그냥 안 보인다.

| 항목 | 값 |
|---|---|
| 캔버스 | 13.333 × 7.5 in |
| **안전 여백** | **0.93 in** (사방) — 프로젝터 가장자리가 잘린다 |
| 본문 영역 | 11.47 × 5.64 in |
| 좌표 단위 | 인치 (소수 셋째 자리까지) |

---

## 2. 타이포 환산표 ★

HTML 뼈대의 스케일을 그대로 옮긴 값이다. **이 표를 벗어나지 않는다.**

| 역할 | HTML | **PPTX** | 쓰는 곳 |
|---|---|---|---|
| 표지 제목 | 92px | **69pt** | `.cover` 한 장 |
| 장 제목 | 64px | **48pt** | 각 장 제목 |
| 중제목 | 46px | **35pt** | 섹션 안 소제목 |
| 본문 강조 | 33px | **25pt** | 리드 문장, 항목 |
| 본문 | 28px | **21pt** | 일반 본문 |
| 큰 숫자 | 205px | **154pt** | `.metric` 숫자 하나 |
| 주석·출처 | 19px | **14pt** | 안 읽혀도 되는 것만 |
| 쪽번호 | 15px | **11pt** | 읽으라고 있는 게 아니다 |

**본문 하한 21pt.** 14pt·11pt 는 주석과 쪽번호 전용이다 — 그 둘 말고 21pt 아래로 내려가는 글자가 있으면 **크기가 아니라 내용이 잘못된 것**이다.

**줄 간격**은 1.3~1.5배. 한글은 영문보다 여유가 필요하다.
**자간**은 `charSpacing` 으로 준다 (`letterSpacing` 이라는 옵션은 없어서 조용히 무시된다). 제목에 -0.5 ~ -1 정도.

---

## 3. 폰트 — 가장 자주 망가지는 곳 ★★

**HTML 뼈대는 Pretendard 를 1순위로 쓴다. PPTX 에서는 그러면 안 된다.**
받는 사람 PC 에 Pretendard 가 없으면 PowerPoint 가 임의 폰트로 바꾸고, **자간·줄바꿈·장수가 전부 틀어진다.** 설명회장 노트북에서 이게 터지면 되돌릴 수 없다.

### 폰트 결정 규칙

| 상황 | 쓸 폰트 |
|---|---|
| **모르는 PC 에서 열린다** (기본값) | **맑은 고딕** — 윈도우에 전부 깔려 있다 |
| 내 PC 에서만 발표한다 | Pretendard 도 가능 |
| 받는 사람이 Mac | 맑은 고딕이 없다 → PowerPoint 가 애플 고딕류로 대체. 크기가 조금 달라지는 것은 감수한다 |
| 인쇄소·기관 제출 | 맑은 고딕 + **파일에 폰트 포함** 저장 |

**나눔고딕·Pretendard·에스코어드림 등은 "있으면 좋은 것"이지 기본값이 아니다.**

### 폰트 포함(임베딩)

PowerPoint 의 `파일 → 옵션 → 저장 → 파일에 폰트 포함` 으로 넣을 수 있다. 다만:
- 한글 폰트는 글자 수가 많아 **파일이 수십 MB 로 커진다**
- 폰트마다 **임베딩 허용 여부가 다르다.** 상업 배포 시 라이선스를 확인한다
- 그래서 **맑은 고딕으로 만드는 편이 언제나 안전하다**

### 숫자

숫자를 세로로 맞출 때는 등폭 숫자가 필요하다. 맑은 고딕에는 등폭 숫자 기능이 없으므로, **표의 숫자는 오른쪽 정렬**로 맞춘다.

## 4. 자동 맞춤 금지 ★★

**PowerPoint 는 텍스트가 넘치면 글자 크기를 제멋대로 줄인다.** 24pt 로 넣어도 14pt 로 축소된다.
이러면 이 킷의 핵심 규칙인 **본문 하한이 그냥 무력화된다.** 뒷자리에서 안 읽히는 슬라이드가 만들어지고, 만든 사람은 모른다.

> **모든 텍스트 상자에서 자동 맞춤을 끈다.**
> 넘치면 **글자를 줄이지 말고 내용을 덜어낸다.** 그게 이 킷의 원칙이다.

넘칠 때의 순서:
1. 문장을 구절로 줄인다 ("~합니다" → 명사형)
2. 항목을 5개 이하로 줄인다
3. 장을 나눈다 — **슬라이드는 공짜다**
4. 그래도 안 되면 그 내용은 슬라이드가 아니라 **배포 인쇄물**로 간다

## 6. 레이아웃 10종 — PPTX 대응

좌표는 13.333 × 7.5 in, 여백 0.93in 기준. `x, y, w, h` 는 인치.

| 패턴 | PPTX 구성 |
|---|---|
| **표지** `.cover` | 제목 69pt 를 아래쪽 정렬 (y 3.6). 위쪽은 비운다. 하단에 14pt 메타 한 줄 + 그 위 가는 선 |
| **한 문장** `.statement` | 제목 48pt, 최대 2줄, `w 8.5in` 로 제한해 자연스럽게 접히게. 세로 가운데 |
| **큰 숫자** `.metric` | 숫자 154pt 한 개. 그 아래 35pt 설명, 14pt 근거. **숫자를 두 개 크게 두지 않는다** |
| **2단 비교** `.split` | 좌우 두 텍스트 상자 (각 `w 5.1in`), 가운데 세로선 1pt. 오른쪽 제목만 강조색 |
| **항목** `.list-slide` | 항목마다 별도 텍스트 상자로 두면 간격을 정확히 준다. 번호는 14pt 강조색, 내용 25pt |
| **도해** `.diagram` | **SVG 를 못 쓴다.** 둥근 사각형 도형 + 화살표 커넥터로 그린다. **상자 5개 상한**. 도형 채움은 배경색, 테두리는 괘선색, 강조 상자만 강조연+강조 테두리 |
| **표** `.table-slide` | 네이티브 표를 쓴다(이미지 금지). 머리행 14pt 대문자·굵게, 본문 21pt. 행 6·열 4 상한. **숫자 열은 오른쪽 정렬** |
| **인용** `.quote` | 35pt 굵게, `w 7.5in`. 아래 14pt 출처. 따옴표를 크게 그리지 않는다 |
| **섹션 전환** `.section-break` | 배경을 제목색(ink)으로 채우고 글자를 배경색으로. 69pt |
| **마무리** `.closing` | 배경 ink. 제목 48pt + 강조색 둥근 사각형 버튼(안에 25pt 굵게). **행동 하나** |

### 도해를 그릴 때

- 상자는 **둥근 사각형**, 모서리 반경은 통일
- 화살표는 **직선 커넥터** — 곡선·꺾인 선을 섞지 않는다
- 상자 안 글자 21pt, 부연 14pt
- 도형에 그림자를 넣지 않는다 (넣더라도 **오프셋은 0 이상**. 음수를 주면 파일이 깨진다)

## 7. PPTX 에서 못 하는 것 — 대체안

| HTML 에서 하던 것 | PPTX | 대체 |
|---|---|---|
| **형광펜 밑줄** (`.mark`) | 그라데이션 배경 없음 | 강조연(soft) 색으로 **채운 얇은 사각형**을 글자 뒤에 두거나, 그냥 강조색 굵게 |
| 등장 애니메이션 | CSS 없음 | PowerPoint 전환 효과 **하나로 통일**. 장마다 다르게 쓰지 않는다 |
| `cqw` 반응형 | 없음 | 고정 인치 좌표 |
| 진행 막대 | — | 하단에 얇은 사각형을 장마다 폭을 늘려 배치 (선택) |
| 다크 테마 토글 | — | 필요하면 **별도 파일**로 만든다 |
| 웹폰트 | — | §3 폰트 규칙 |

**그라데이션은 쓰지 않는다.** 필요하면 배경 이미지로 넣되, 우리 거부 목록에 그라데이션 강조가 이미 들어 있으니 대개는 안 쓰는 게 맞다.

## 8. 만들고 나서 — 반드시 확인

- [ ] **캔버스가 13.33 × 7.5 in 인가** (10in 기본값이면 좌표가 다 어긋난다)
- [ ] 모든 글자가 **21pt 이상**인가 (주석·쪽번호 제외)
- [ ] **자동 맞춤이 꺼져 있는가** — 켜져 있으면 위 검사가 무의미하다
- [ ] 폰트가 **맑은 고딕**인가 (또는 받는 PC 에 확실히 있는 것인가)
- [ ] 색에 `#` 이 섞이지 않았는가
- [ ] 안전 여백 0.93in 안에 내용이 들어와 있는가
- [ ] 표가 이미지가 아니라 **네이티브 표**인가
- [ ] 전환 효과가 **하나로 통일**돼 있는가
- [ ] **실제로 열어서 슬라이드쇼로 돌려봤는가** ★
- [ ] 가능하면 **다른 PC 에서 한 번 열어봤는가** — 폰트 문제는 그때만 드러난다

그리고 이 킷의 공통 검수를 그대로 통과시킨다 — 실눈 검사, 거부 목록, 한 장 한 메시지, 마지막 장 행동 하나, 한글 문체.

## 9. 파일을 넘길 때

- 파일명에 **날짜와 대상**을 넣는다 — `공감영어_예비고1설명회_2026-12-02.pptx`
- **PDF 도 함께** 준다. 받는 사람 PC 에서 깨졌을 때의 정답지가 된다
- 수정을 부탁할 거면 **어느 장 어느 부분인지** 쪽번호로 지정한다
