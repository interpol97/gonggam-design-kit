# 업무 플로우 — 무엇을 묻고, 어떤 순서로 만드나

> 덱 제작 요청이 들어오면 **이 순서대로** 진행한다.
> 사용자가 이미 준 정보는 다시 묻지 않는다. 빈 칸만 묻는다.

---

## 0단계 — 소재부터 확인한다 (묻기 전에)

**먼저 볼 것이 있는지 확인한다.** 있으면 대부분의 질문이 저절로 채워진다.

- 첨부한 파일 (한글·워드·PDF·엑셀·기존 PPT·사진)
- 붙여넣은 글
- 지난 대화에서 만든 자료

있으면 **읽고 나서** 아래를 묻되, 읽어서 아는 것은 **확인만** 받는다.
없으면 "무엇을 가지고 만들까요 — 자료가 있으면 올려 주시고, 없으면 대화로 만들겠습니다"로 시작한다.

---

## 1단계 — 한 번에 묶어 묻는다

**질문을 하나씩 던지지 않는다.** 아래를 한 화면에 묶어 묻고, 답을 받아 한 번에 진행한다.
사용자가 모르겠다고 하면 **기본값으로 진행하고 나중에 바꿀 수 있다고 알린다.**

### 필수 5

| # | 묻는 것 | 선택지·기본값 |
|---|---|---|
| 1 | **주제** — 무엇에 대한 발표입니까 | (자유 입력) |
| 2 | **모드** — 청중이 무엇을 하면 성공입니까 | **설득**(결정·신청) / **강의**(이해·기억) / **보고**(근거 확인) |
| 3 | **청중** — 누가, 몇 명, 어디서 봅니까 | 예: 학부모 40명 · 저녁 강의실(불 켬) · 빔프로젝터 |
| 4 | **임무** — 발표가 끝나고 **딱 하나** 하게 만들 행동은 | 예: 개별 상담 신청 |
| 5 | **분량** — 발표 몇 분입니까 | 기본 20분 → **12~15장** (계획의 70%) |

### 선택 5 — 안 물어도 되지만 있으면 좋다

| # | 묻는 것 | 기본값 |
|---|---|---|
| 6 | **제목** — 표지에 넣을 말 | 없으면 **3안을 만들어 고르게 한다** |
| 7 | **디자인 테마** | 아래 표에서 고르게. 기본 `t-trust` |
| 8 | **브랜드 색** — 학원 대표색 hex가 있으면 | 있으면 테마 대신 그 색으로 `--accent` 지정 |
| 9 | **로고·사진** — 넣을 이미지가 있으면 | 없으면 넣지 않는다 (빈 자리를 만들지 않는다) |
| 10 | **금지 사항** — 쓰면 안 되는 표현·숫자 | 없으면 표준 검수만 |

### 7번 테마 선택지 (그대로 보여준다)

| 고르는 말 | 테마 | 성격 |
|---|---|---|
| 신뢰감 있게 | `t-trust` | 코발트블루 · **설명회 기본값** |
| 친근하게 | `t-fresh` | 초록+노랑 · 초중등 |
| 차분하게 | `t-forest` | 진초록 · 정통 |
| 학습·성취 느낌 | `t-mint` | 민트+블루 · 중고등 |
| 단정하게 | `t-clear` | 맑은 파랑 |
| 한국형 친근 | `t-friendly` | 토스풍 파랑 |
| 학술적으로 | `t-academy` | 짙은 파랑 |
| 선명하게 | `t-cobalt` | 코발트 |
| 세련되게 | `t-violet` | 보라 · 특강 |
| 따뜻하게 | `t-sunrise` | 크림+주황 · 초등 |
| 활기차게 | `t-mango` | 주황 · 모집 |
| 주목시키기 | `t-focus` | 레드 · 마감 고지 |
| 따뜻한 주목 | `t-coral` | 코랄 |
| 성장 느낌 | `t-sprout` | 연두 |

전부 **밝은 배경**이다. 어두운 배경은 화면 공유 발표일 때만(`dark`).

---

## 2단계 — Design Read 를 한 줄로 되짚는다

받은 답을 **한 문장으로 확인받는다.** 여기서 어긋나면 다 만들고 뒤집는 것보다 싸다.

> "설득 덱으로 읽었습니다. 예비고1 학부모 40명, 저녁 강의실(불 켬), 임무는 개별 상담 신청 하나, 25분 · 14장, 테마는 신뢰형(코발트블루). 이대로 갈까요?"

## 3단계 — 목차를 먼저 낸다 (장표를 만들기 전에)

**바로 만들지 않는다.** 장별 제목과 레이아웃만 표로 낸다.

| 장 | 제목 | 레이아웃 |
|---|---|---|
| 1 | (표지 제목) | `.cover` |
| 2 | 중3까지 80점대였던 학생이 52점을 받습니다 | `.statement` |
| 3 | 하위권 오답 68%가 어법 | `.metric` |
| … | | |
| 14 | 개별 상담 신청하기 | `.closing` |

여기서 확인할 것:
- 같은 레이아웃이 **3연속**인 곳은 없는가
- 마지막 장이 **행동 하나**인가
- 장수가 분량에 맞는가 (1장 ≈ 1.5~2분)

승인받고 나서 만든다.

## 4단계 — 만든다

`templates/deck.html` 을 복사해 채운다. **처음부터 CSS를 짜지 않는다.**
패턴별 규칙은 `layouts.md`. 문구는 `korean-writing`.

## 5단계 — 검수하고 넘긴다

`SKILL.md` 의 검증 목록을 돌린다. 특히 **실제로 띄워 보고 뒤에서 읽어봤는가.**

그다음 사용자에게 셋 중 무엇이 필요한지 묻는다.

| 필요한 것 | 어떻게 |
|---|---|
| **그대로 발표** | 브라우저로 열고 `F` 전체화면. `←→` 이동 |
| **PDF로 배포** | `P` 눌러 인쇄 → PDF로 저장 |
| **PPTX로 직접 수정** | `pptx-spec.md` 규격으로 `.pptx` 를 만든다. **HTML 을 변환하는 게 아니라 규격에 맞춰 새로 짠다** |

PPTX 로 갈 때는 **폰트를 맑은 고딕으로 바꾸고 자동 맞춤을 끈다** — 안 그러면 받는 PC 에서 깨지고 글자가 줄어든다.

**배포용 인쇄본**이 따로 필요한지도 묻는다 — 슬라이드를 그대로 인쇄하면 여백투성이라, A4 1~2장으로 다시 짜는 편이 낫다.

---

## 다시 묻지 않는 것

한 번 받은 답은 **그 대화 안에서 다시 묻지 않는다.** 특히 청중·조명·임무는 덱 전체를 지배하므로 처음에 받아 끝까지 유지한다.
사용자가 중간에 "테마 바꿔줘"라고 하면 **토큰만 갈아끼운다.** 내용을 다시 만들지 않는다.

## 사용자가 급할 때

"그냥 빨리 만들어줘"라고 하면 **1·3번만 묻고** 나머지는 기본값으로 간다.

> 주제 / 청중 → 나머지는 설득 모드 · `t-trust` · 12장 · 20분

만든 뒤에 "테마와 장수는 바꿀 수 있습니다"라고 알린다.
